BUG #2: Destructor - Missing pthread_join() (Line 31-35)
─────────────────────────────────────────────────────────
❌ ORIGINAL (BUGGY - THIS IS THE MAIN CRASH CAUSE):
   AlsaMidiSequencerInputClient::~AlsaMidiSequencerInputClient()
   {
	   close_seq();
	   stop_midi_in_seq_client_thread();  // ← Just sets flag, doesn't wait!
   }                                      // ← Destructor returns immediately!
										 // Thread STILL RUNNING!

PROBLEM: The destructor returns while the thread is still running and using
		 alsa_seq_client_rx_queue. When the caller destroys the queue,
		 the thread accesses freed memory → CRASH at 0x5555!

✅ FIXED:
   AlsaMidiSequencerInputClient::~AlsaMidiSequencerInputClient()
   {
	   // STEP 1: Signal thread to stop
	   midi_in_client_thread_is_running = false;

	   // STEP 2: Wake thread if it's waiting in queue
	   if (alsa_seq_client_rx_queue) {
		   alsa_seq_client_rx_queue->shutdown();
	   }

	   // STEP 3: CRITICAL - Wait for thread to exit
	   if (midi_client_in_thread) {
		   pthread_join(midi_client_in_thread, nullptr);  // ← WAIT HERE!
		   midi_client_in_thread = 0;
	   }

	   // STEP 4: Now safe to close sequencer
	   close_seq();
   }


BUG #3: Thread Function - No shutdown check (Line 119-125)
───────────────────────────────────────────────────────────
❌ ORIGINAL (UNSAFE):
   if (ret > 0 && ev != NULL)
   {
	   qev = new snd_seq_event_t();
	   memcpy(qev, ev, sizeof(snd_seq_event_t));
	   alsa_seq_client_rx_queue->enqueue(qev);  // ← No check!
	   snd_seq_free_event(ev);
   }

PROBLEM: If shutdown happens between the memcpy and enqueue,
		 the enqueue could happen on a shutting-down queue.

✅ FIXED:
   if (ret > 0 && ev != NULL)
   {
	   qev = new snd_seq_event_t();
	   memcpy(qev, ev, sizeof(snd_seq_event_t));

	   // Check if still running before enqueue
	   if (midi_in_client_thread_is_running && alsa_seq_client_rx_queue) {
		   alsa_seq_client_rx_queue->enqueue(qev);
	   } else {
		   // Shutting down, clean up
		   delete qev;
	   }

	   snd_seq_free_event(ev);
   }

═══════════════════════════════════════════════════════════════════════════
							  WHY THESE FIXES
═══════════════════════════════════════════════════════════════════════════

THE CRASH SEQUENCE (Before Fix):
1. Destructor called
2. close_seq() closes ALSA sequencer
3. stop_midi_in_seq_client_thread() sets flag to false
4. Destructor RETURNS (thread still running!)
5. Caller destroys SafeQueue
6. Thread tries to enqueue() → accesses freed memory → CRASH at 0x5555

THE SAFE SEQUENCE (After Fix):
1. Destructor called
2. Set running flag to false
3. Call queue->shutdown() to wake waiting thread
4. pthread_join() - WAIT for thread to completely exit
5. Destructor RETURNS (thread has exited)
6. Caller destroys SafeQueue safely (no one using it)
7. ✓ No crash!
